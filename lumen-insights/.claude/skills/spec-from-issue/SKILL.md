# Spec from issue

1. Read the issue with `gh issue view <n>`, its comments and linked PRs.
2. Ask me the questions the issue leaves open, then brainstorm two or three approaches and recommend one.
3. Write `docs/specs/<n>-<slug>.md`: intent, approach, impacts on existing KPIs, open questions.
4. Do not start coding until I approve the spec.
