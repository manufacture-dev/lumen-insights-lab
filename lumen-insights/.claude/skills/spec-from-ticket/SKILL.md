# Spec from ticket

1. Read the ticket in `work/`, its log and the tickets it links to.
2. Ask me the questions the ticket leaves open, then brainstorm two or three approaches and recommend one.
3. Write `docs/specs/<n>-<slug>.md`: intent, approach, impacts on existing KPIs, open questions.
4. Do not start coding until I approve the spec.
